### Added

- **Grow Room Dashboard — Next Watering Estimate**: Added estimated next watering timestamp detection via three new template sensors (`sensor.grow_room_next_watering_estimated`, `sensor.grow_room_watering_status`, `sensor.grow_room_days_since_watered`), four helper entities (`input_datetime.grow_room_last_watered`, `input_number.grow_room_watering_interval_avg`, `input_boolean.grow_room_soil_armed`, `counter.grow_room_watering_events`), and a new automation `grow_room_detect_watering` in `automations.yaml`. Since the setup is hand-watered (no pump/valve relay signal), watering cycles are inferred from the soil moisture curve's sawtooth pattern using hysteresis thresholds (45%/60% crossings); detected intervals feed an adaptive EMA (alpha=0.4) rather than a plain mean, allowing the estimate to drift with the plant's current watering cadence. Confidence gate requires ≥3 observed cycles before displaying a real ETA; during learning phase the dashboard shows "Learning… (n/3 cycles)". This feature also logs a calendar-backed "Days Since Watered" counter for trend analysis. Important note for maintainers: `input_datetime` values are naive (no timezone); any arithmetic must wrap `as_datetime()` in `as_local()` before offset or comparison with `now()` to avoid silent calculation errors. A tz-handling bug was discovered and fixed post-QA; see `packages/botanical_bay.yaml` header for details.

- **Climate Control — Brent's Room Occupancy Override**: Added `input_boolean.brent_room_occupied` (default off, manual toggle, no auto-reset) to conditionally exclude Brent's Room from house-wide climate logic when unoccupied. Brent's Room is occupied only 2–3 nights per month; its temperature and humidity readings were previously unconditionally included in all climate decisions: house average calculations (feeding T6 setpoint offsets), room-spread detection (controlling continuous blower mode), and dehumidifier hysteresis (force-on threshold and allow-off conditions). An unoccupied room's readings distorted these calculations, pushing the house average warmer/cooler than the occupied spaces, artificially inflating the spread, and indefinitely blocking dehumidifier shutoff. Now `sensor.house_average_temperature` and `sensor.house_average_humidity` use dynamic lists (4 core rooms + Brent's Room when toggle is on, divided by actual count). The `climate_apply_setpoints` automation's spread calculation excludes Brent's Room when off. Dehumidifier force-on automation suppresses triggering from Brent's Room sensor alone when toggle is off; allow-off automation permits shutoff when other four rooms are ≤40%, regardless of Brent's Room state, if toggle is off. When toggle is on, all readings are included as before. No auto-reset by design — automatic reset would wrongly interrupt multi-night occupancy.

### Fixed

- **Chopper Lawn Mowing — Zone-Rotation Variables Type-Preservation Bug**: Fixed `chopper_auto_mow_clear_morning` automation failing silently at scheduled 11:00am trigger on 2026-07-13 (and likely all prior scheduled runs) with zero trace in the system log. Root cause: automation's `variables:` block had an intermediate `chopper_all_zone_switches` variable holding a list of HA State objects, which it passed to a downstream variable (`chopper_target_switch`) via reference. Home Assistant only preserves native Python types across a variable boundary when the rendered string round-trips cleanly through `ast.literal_eval` — a list of State objects does NOT round-trip (its repr like `[<state switch.foo=on>, ...]` is not valid Python syntax), so HA silently fell back to storing the raw string representation instead. Downstream `selectattr()` and `rejectattr()` filters then iterated over that "list" character-by-character instead of as objects, throwing `UndefinedError: 'str object' has no attribute 'attributes'` and aborting the automation 0.01 seconds into the variables step with no entry in the system log — only the automation's own execution trace revealed the failure. Fix: removed the intermediate variable entirely and inlined the full `states.switch | selectattr | selectattr | map | list` pipeline directly into both `chopper_target_switch` and `chopper_other_switches`, ensuring only scalar strings and lists-of-strings (which DO round-trip through literal_eval) ever cross variable boundaries. Also added `| default('', true)` guard after `| first` for robustness (empty string fallback if no switch matches, allowing the downstream `switch.turn_on` with empty entity_id to fail safely rather than raising in the template engine). QA confirmed no other `variables:` block in automations.yaml exhibits this pattern — the other 3 blocks only chain scalars or literal YAML dicts, both of which round-trip cleanly.

- **Chopper Lawn Mowing — Zone-Rotation Automation Start-Sequence Race Condition**: Fixed `chopper_auto_mow_clear_morning` automation failing to start mowing after zone selection. Root cause: zero-delay sequence of `switch.turn_off` (deselecting other zones) immediately followed by `lawn_mower.start_mowing` was racing against LUBA integration's laggy command propagation (state changes observed taking 15–20+ seconds to register). Mow start command issued before zone selection had settled, causing LUBA firmware to ignore or reject the start request. Fix: inserted 10-second `delay` between zone-switch changes and the `start_mowing` call, matching the precedent set by `chopper_resume_after_charge` (which uses a 2-minute settle delay before its own `start_mowing` call for a different reason — battery-reading stabilization). Automation now reliably starts mowing on manual trigger and scheduled runs.

  - Renamed "Ship Comms" → removed (consolidated into Media).

  - Merged "Terrain Operations" + "Kamino Station" → "Lawn & Pool" for outdoor control and pool monitoring.
  - Renamed "Botanical Bay" → "Grow Room" (entity IDs unchanged — coordinated boundary with grow_sre repo).

- **Card Substitution**: Replaced all custom `imperial-*` card types with standard Lovelace cards throughout (`entities`, `tile`, `clock`, `picture-entity`, `picture-glance`). Retained `imperial-alert-panel` only (no standard-card equivalent for its dynamic low-battery/offline entity scanning).

- **Configuration Dashboard Titles**: Updated `configuration.yaml` lovelace dashboard titles to plain names:
  - "Imperial Command Center" → "Home".
  - "Cadet's Barracks" → "Cat's Room".

- **Zero Entity Changes**: No entity IDs were renamed or dropped. This was a presentation-layer redesign only, verified by full QA diff against `ui-lovelace.imperial.yaml.bak`.

- **Sibling Dashboard Redesign (Follow-up)**: Converted `ui-cadets-barracks.yaml` and `ui-manufacturing.yaml` to align with main dashboard standards:

Intentionally **retained** `custom:imperial-fleet-grid` in Fleet view — this card performs cross-prefix printer normalization across Bambu/Klipper/PrusaLink integrations with no standard-card equivalent. Replaced custom icon-pack references (`local:galactic-republic`, `local:old-republic`) with `mdi:*` icons throughout.
  - **Known Tradeoff**: Flsun S1 Pro camera in manufacturing dashboard now displays sideways (was previously rotated 90° by removed `imperial-camera` custom card). User explicitly approved this tradeoff rather than keeping a single-use custom card.
  - Backups preserved: `ui-cadets-barracks.imperial.yaml.bak`, `ui-manufacturing.imperial.yaml.bak`.
  - Zero entity ID changes. Presentation-layer redesign only.
